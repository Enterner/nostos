# nostos 代码审查报告（2026-10-25）

> 范围：全部 39 个第一方文件（include/nostos/** 32 个头、src/ 2 个实现、cmake/ 3 件、
> README/src README/注释规范/AGENTS、CMakeLists、CMakePresets），逐行通读。
> 疑似 bug 用 MinGW g++ -std=c++20 在系统临时目录编译复现（仓库未改动）。

## 总评

整体质量高：include/src 分离、L0→L1→L2→kit 分层、冻结 C ABI 独立目录、umbrella 头
刻意不含插件侧——都是教科书形态；头注释的 why 密度明显高于平均水准，与注释规范自洽。

三个问题域各有一个头条：

1. **冗余**：`Scope::effect` 是"参数多处使用、每处都写右值"的实证级 bug（label 恒为
   空串 + teardown 段错误）；`abi::Host` 的能力门控是系统性的双/三重检查（12 处）。
2. **框架**：结构本身符合主流，最大的读者陷阱是 `docs/注释规范.md` 整份从另一个项目
   （ithaca）拷来，示例指向本仓不存在的文件。
3. **不一致**：README 停留在 slot/poster/LazyGate/对话框重构引入之前，共 8 处漂移；
   另有 2 处注释声称的保障与代码不符。

## 一、冗余写法

### 1. 🔴 `Scope::effect`：参数先 move 后再用 + `erase(end())` UB（已复现崩溃）

`include/nostos/scope.hpp:109-117`

```cpp
void effect(std::string label, std::function<void()> body) {
    auto labels = live_labels_;
    defer([labels, label = std::move(label), body = std::move(body)]() mutable {
        auto& v = *labels;
        v.erase(std::find(v.begin(), v.end(), label));   // ③ find 失败返回 end()
        body();
    });
    live_labels_->push_back(std::move(label));           // ② 参数已被 ① 搬空
}
```

两个连环 bug：

- ① init-capture `label = std::move(label)` 在 lambda 构造时就把函数参数搬空；随后
  `push_back(std::move(label))` 塞进去的是空串——`get_effects()` 返回的永远是空 label。
- ③ vector 里存的是 `""`，teardown 时 `std::find` 找不到真实 label 返回 `end()`，
  `v.erase(end())` 是未定义行为。

实测（MinGW g++ -std=c++20，临时目录）：

```
labels.size=2
  label=[]
  label=[]
E: before reset
Segmentation fault (core dumped)
```

同函数注释（:107-108「登记 ⇒ 立即执行 body；label 的摘除发生在 body 之后」）与实现
（body 延迟到 teardown、erase 在 body 之前）也对不上。修法三处一起改：

```cpp
defer([labels, label, body = std::move(body)]() mutable {   // label 按值捕获（拷贝）
    auto& v = *labels;
    if (auto it = std::find(v.begin(), v.end(), label); it != v.end()) v.erase(it);
    body();
});
live_labels_->push_back(std::move(label));   // 参数此刻仍完好
```

该 API 在仓内无调用方、README 也未提及，但它是对外公开的 L0 接口——修或删，二选一。

### 2. 🟡 `abi::Host` 系统性双/三重门控（约 12 处）

`include/nostos/abi/plugin.hpp:106,111,121,130,174,192,205,217,224,231` 等，典型形态：

```cpp
if (!valid() || !NOSTOS_HOST_HAS(api_, acquire_poster) || api_->acquire_poster == nullptr)
```

按 ABI 自身契约（nostos_abi.h 纪律 4「只解引用写入方承诺已写过的字段」；
host_api.hpp:57「每个字段——包括 v1 冻结之后追加的字段——都已填充」）：

- v1 字段：`valid()` 一道已够（struct_size ≥ V1_SIZE ⇒ 字段存在且已填）；
- 追加字段：`NOSTOS_HOST_HAS` 一道已够（宏自带 `api_ != NULL` 与大小门控）。

`api_->x == nullptr` 的复检只在「宿主对 struct_size 撒谎」时有意义——那种宿主本来就
违约了。而且 plugin.hpp:117-119 自己写明设计意图：「于是调用方统一按'没有投递器'处理，
不必手工探查 struct 大小」——实现却处处多层。同类问题：`Host::service<T>()`（plugin.hpp:88-91）
先 `valid()` 再调 `query<T>`，而 query（interface.hpp:105-109）把 struct_size /
abi_version / service 非空又全查一遍。建议定一个口径：宿主侧能力探查只认
`NOSTOS_HOST_HAS`（v1 字段加 valid()）一层，全类统一。

### 3. 🟡 `Host::check_component` 的 `static_assert(Component<C>)` 不可达

`include/nostos/host_builder.hpp:43-44` 类模板已带 `requires (Component<Cs> && ...)`：
约束不满足时类直接出局，构造函数体（连同 :226-227 的 static_assert 及其友好文案）
永远不实例化。这条断言是死代码——要么删 requires 子句让文案可达，要么删断言留
requires（后者是主流做法）。同函数里 onStop-noexcept 与 well_formed 两条断言是活的，
不受影响。

### 4. 🟡 `DynamicPlugin::load` 与 `LinkedPlugin::attach` 重复同一段入口解析

`src/loader/loader.cpp:282-289` vs `include/nostos/linked_plugin.hpp:52-60`：
「调 entry() → catch → 转 plugin_error（连文案都逐字相同）」在两种模式各写一遍。
本仓设计哲学是「两种模式共用逻辑」（PluginSession 已收编会话/回滚/状态转移），
这段也应收进 PluginSession 或一个 `resolve_entry(entry, source)` 自由函数。

### 5. 🟡 `table_is_valid` 是死 API，`PublishedRegistry::add` 又内联重写了它

`include/nostos/abi/interface.hpp:79-83` 全仓零调用（grep 确认）；`published.hpp:31-41`
的 `add()` 把 null / struct_size / abi_version 三道检查原样再写一遍（为区分 Reason
文案可以理解）。要么 `add()` 调 helper 再补差异文案，要么删掉 helper。

### 6. 🟢 杂项（小而确定）

- `src/kit/http.cpp:369-370`：`if (client.request_done) continue; continue;`——两支都
  continue，第一个 if 是死分支。
- `src/kit/http.cpp:457-458` 与 `flush()` 内部（:475）：`respond()` 尾部的
  `maybe_finish()` 与 flush 排空路径里的那次幂等重复；`reap()`（:499-514）对
  `fd == kInvalidSocket` 做两轮 remove_if，可合并为一轮。
- `include/nostos/kit/config.hpp:183-185`：`is_number()` 分支与最后的 else 完全相同
  （都是 `node.dump()`），number 分支冗余。
- `kit/process.hpp` / `kit/piped_process.hpp` / `kit/win.hpp`：三个头各自重复
  `WIN32_LEAN_AND_MEAN`/`NOMINMAX` 模板——把 win.hpp 放最前 include 即可消掉两份。
- `cmake/plugin_module.cmake:52`：MSVC 分支 `/permissive- /EHsc` 与 `nostos::core`
  INTERFACE 已带的同名选项（CMakeLists.txt:41）重复（插件目标已链 nostos::core）。
- `CMakeLists.txt:14,21`：`project(... VERSION 0.1.0)` 与 `set(nostos_VERSION 0.1.0)`
  双写同一字面量（后者服务 add_subdirectory 场景，值得注释说明或收敛为单一变量）。
- 分层可辩护的重复，仅提示：`loader.cpp:45-61` 的 `to_wide/to_utf8` 与
  `kit/win.hpp` 的 `utf8_to_wide/wide_to_utf8` 两套同功能实现（core 不依赖 kit，成立；
  但 loader 版少了 kit 版的失败防御）；`EventHub` 的 `raw_` + `slot_raw_` 双容器
  （event.hpp:452-453）可用单一 `(evt_id, slot)` 键容器替代（广播即 slot=0），
  off_raw / emit_slot / knows 的双路逻辑随之消失。

## 二、文件框架（读者视角）

**结论：符合主流，执行得好，不需要大动。** 可优化点按对读者的影响排序：

1. **`docs/注释规范.md` 整份从另一个项目（ithaca）拷来**。标题「ithaca 注释规范」，
   参考示例指向 `plugins/webui/plugin.cpp`、`ui/src/store.js`，开头自指
   `docs/测试规范.md`——本仓均不存在。它是 AGENTS.md 指定的单一事实源，读者按图索骥
   全部扑空。建议把示例换成 nostos 自己的（scope.hpp / host_api.hpp 的头注释就是现成
   好例子），.mjs/.vue 等无关条目一并裁掉。
2. **悬空的文档引用链（monorepo 拆分残留）**：`src/README.md:6` 指 `docs/design.md` §6、
   `README.md:99` 指「设计文档 §7」、`README.md:15`「仓库里的其它两个工程」、
   `src/README.md:12`「宿主应用在 app/，插件在 plugin/」、`cmake/plugin_module.cmake:20-26`
   「内核自带示例宿主（app/contract.hpp）」——本仓均不存在。与 b9cb9b4 清理
   test_executor 悬空引用是同一性质，建议再清一轮。
3. **`published.hpp` 层标签漂移**：头注释自称「nostos L2」（published.hpp:2），README
   却列在「2. 组合层（L1）」表里。取一个。
4. **两个同名 `Subscription`**：`nostos::Subscription`（event.hpp:65，控制块+unlink）
   与 `nostos::abi::Host::Subscription`（plugin.hpp:146，token+keep_alive）语义完全
   不同；嵌套作用域隔离了它们，但 grep 到第一个时容易误认。可把 ABI 侧改名
   （如 `AbiSubscription`）。
5. **命名风格双轨**：错误家族全 snake_case（`missing_service`…），其余类型全
   CamelCase。若刻意模仿 std 异常家族，值得在 error.hpp 头注释说一句；否则统一。
6. **vendored nlohmann 的安装位置**：`CMakeLists.txt:130-131` 把
   `third_party/nlohmann/json.hpp` 装到 `<prefix>/include/nlohmann/`，且 `nostos::kit`
   的 INSTALL_INTERFACE 暴露顶层 include——消费者若自带不同版本 nlohmann 会被顶掉或
   顶掉本包，典型 ODR 冲突源。建议装到 `include/nostos/third_party/`，config.hpp 的
   include 改带前缀路径。
7. **`/utf-8` 未挂到内核目标**：core 是 INTERFACE 库、loader.cpp 全中文注释，只有插件
   目标加了 /utf-8（plugin_module.cmake:52）。BOM-less UTF-8 按 ACP 误读时，注释尾
   字节撞上 0x5C 会吞掉下一行——现在没撞是运气。建议挂到 `nostos` INTERFACE。
8. 小点：`abi/plugin_info.hpp:33-39` 在 abi/ 目录里向 `namespace nostos` 注入
   `using PluginInfo`——有注释解释，但让「ABI 冻结面」目录变成 C++ 核心命名的出口；
   `context.hpp` 一文件装 HostCore+Context 两类，可辩护（Context 强依赖 HostCore），
   保持现状即可。

## 三、文档与实现不一致

1. **README 的 kit/win.hpp 行已过时**（README.md:73）：写「文件选择对话框 + UTF-8
   转换」——对话框在 123f938 已「出内核」，win.hpp 现在只有 UTF-8 转换。
2. **README 的 host_api.hpp 行计数过时**（README.md:58）：「7 个 thunk
   （service/on/off/log + publish/unpublish/emit）」——实际 11 个函数槽
   （+acquire_poster / published_list / on_slot / emit_slot）。
3. **README 的 event.hpp 行缺 slot 维度**（README.md:45）：on_slot/emit_slot 单播
   通道（58dc137）没有进 README 的 L1 表。
4. **README kit 表缺两个成员**：`kit/poster.hpp`（poster_submit / poster_submit_await）
   与 `kit/piped_process.hpp`（PipedProcess）；`loader.hpp` 行也没提 LazyGate 与
   manifest 懒激活。
5. **README「不提供什么」与 LazyGate 矛盾**（README.md:99）：「还没有：PENDING 自动
   重激活」——`LazyGate::pump_into`（loader.hpp:144，实现 loader.cpp:355-373）做的就是
   PENDING 依赖齐后自动拉起。内核不自动、宿主装配才生效，但条目至少要加注。
6. **README 错误家族清单不全**（README.md:38）：漏 `undeclared_require` /
   `declared_type_mismatch` / `bad_published_table` / `host_state_error`。
7. **README 快速上手 B 的代码块没有闭合围栏**（README.md:131-146）：```cpp 开在 B 节，
   直到「## 许可」前没有 ```，许可整节被渲染进代码块。
8. **nostos_services.h 承诺的供货方不存在**：头注释说「每张表由 nostos-kit（Tier 1）
   供货」（nostos_services.h:3）、`kit/log.hpp:8` 也说「ABI 插件经 nostos_log_v1 表
   取用」——但全仓没有任何把 kit::Log 包成 nostos_log_v1 表的适配代码。声明与实现
   二缺一。
9. **`end_session` 的 drop 回调注释称「宿主侧再兜底一层」，实际没有兜底**
   （host_api.hpp:158）：`drop(task.second)` 无 try/catch，`end_session` 是 noexcept
   （:121）——插件 drop 回调抛异常 = 整个宿主 terminate。同文件 `drain_posted`
   （:267-271）对同类 fn 有 catch + 日志。两条执行路径行为不一致，且 c016617 的
   「吞掉不再无声」没覆盖这条。
10. **`acquire_poster` 的会话纪律有文档无执法**：nostos_abi.h:143-146 说「在 activate
    期间调用」；publish_thunk 对同类越界返回 BAD_STATE（host_api.hpp:458 的
    `in_session()` 检查），acquire_poster_thunk（:218-226）只查 TLS 桥不查会话——
    排水任务（drain_posted 的 Guard 内）或 published 表回调里领取的 poster 落进
    `session_posters_` 却无会话标记，下一次最外层会话收尾（poster_from=0）把它一并
    作废，语义含糊。补 in_session 执法（与 publish 对齐）或文档改口。
11. （同第一节 #1）`Scope::effect` 的注释与实现相互矛盾。

## 建议优先级

- **P0**：修 `Scope::effect`（按值捕获 label + erase 判空，三行改动）。
- **P1**：统一 ABI 能力门控口径（一处宏/一层检查）；`end_session` 的 drop 补
  try/catch（与 drain_posted 对齐）；`acquire_poster` 补 in_session 执法或文档改口。
- **P2**：文档对齐批次（三-1～7、二-1～2），注释规范文档本地化。
- **P3**：死代码清理（table_is_valid、check_component 断言、http 死分支、config
  冗余分支）；结构小优化（同名 Subscription、nlohmann 安装位、/utf-8、EventHub
  容器合一）。
