# nostos 注释规范（所有 agent 与开发者共用）

> 单一事实源。语言：**中文**（技术名词保留英文原词，不翻译）。

## 原则

1. **注释写 why，代码写 what。** 代码本身能看出来的，不写注释。
2. **注释自包含——代码是第一信息获取源。** 不写「详见 docs/xxx」「方案 §N」这类外指：
   注释要成立，必须把约束/背景/口径本身写进注释里。文档可以存在，但代码注释不依赖它。
3. **陈述现状与不变式，不陈述历史。** 注释是给「半年后读代码的人」看的——他不知道
   旧行为是什么。「不再…」「已退役…」「修了…」这类变更日志式注释会随时间失效。
   历史进 commit message；注释里只留对新读者仍有价值的部分（约束的证据、事故的后果）。
4. 注释密度向「藏 complexity 的地方」倾斜：线程纪律、所有权与生命周期、ABI 边界、
   契约顺序——这些是注释的主战场；普通业务代码保持稀疏。

## 注释标记（统一前缀，可 grep）

| 标记 | 用途 | 示例 |
|------|------|------|
| `NOTE:` | 代码看不出来的约束/设计决定 | `NOTE: 能力门控只做一层——v1 字段用 valid()，尾部追加字段用 NOSTOS_HOST_HAS`（abi/plugin.hpp） |
| `踩过:` | 违反上述约束的真实事故（接在 NOTE 后作证据） | `踩过: 插件事件回调内抛出被静默吞掉、同事件的其他订阅者也没跑`（abi/host_api.hpp） |
| `TODO:` | 已知的待办，写明方向 | `TODO: 需要时补 posix 分支，与 process.hpp 同批`（kit/piped_process.hpp） |
| `HACK:` | 明知的取巧，说明为什么可以接受 | — |

## 各位置的写法

### 文件头（每个 .cpp/.h）

一段职责说明 + 关键设计决定（**自包含**——不指向方案/设计文档，背景写进注释本身）。
本仓的现成范例：`src/loader/loader.cpp`（include 顺序纪律：平台头关进单个 TU）、
`include/nostos/abi/host_api.hpp`（线程局部"当前桥"的解析规则、吞异常的口径）。
不加版权/license 头——**闭源开发期不需要**；将来公开时统一补 SPDX 行
（`// SPDX-License-Identifier: <协议>` + 版权行），到时一次性脚本处理，平时不写。

### 分节横幅

大文件用 `// ---- 分节名 ----` 分节（现有风格），节名说职责不说过渡（写「会话注册表」
不写「辅助函数」）。

### 变更日志式注释的改写（存量，遇到就顺手改）

主句陈述现状规则；「踩过:」只留后果作证据。对照示例：

- ✗ `不再用 typeid 做 registry 键（已换掉，跨编译器有问题）`
- ✓ `NOTE: registry 以编译期名字哈希（svc_id）为键——typeid/std::type_index 跨编译器
  不稳定，跨 ABI 域的身份只能靠名字`

- ✗ `修"慢客户端拖死所有人"：之前是每连接一线程`
- ✓ `NOTE: 每客户端有界缓冲做背压——读得慢的连接只是自己缓冲填满、被丢弃，不可能
  拖住 select 循环里的别人`

改写判据：把注释读给一个没看过 git log 的人——他能懂当前规则，即为合格。

### 公开面必须补文档注释（内部函数保持稀疏）

nostos 的公开面是各头文件的公共 API：每个对外函数/模板用一段文档注释说明契约——
职责、前置条件、失败行为、所有权/生命周期。本仓的现成范例：

- `include/nostos/context.hpp` 的 `publish()`：谁拥有表、何时自动撤销、何时该改用
  `publish_static()`；
- `include/nostos/kit/poster.hpp` 的 `poster_submit`：返回码语义、"post 失败谁删"与
  on_drop 两条回收路径。

  ```cpp
  // 把 fn（可调用对象，可带捕获）打包成堆块经 poster 投递，返回 post 的状态码。
  //   NOSTOS_OK        —— 已入队：宿主线程执行后自毁；
  //   NOSTOS_ERR_BAD_STATE —— poster 未领取……未入队，无副作用；
  //   其余（会话作废的 BAD_STATE 等）—— 未入队，载荷已就地回收。
  ```

### 事件与契约注释

跨端点/跨事件的隐式契约必须写在生产者处（消费者处可留一行指回）：广播顺序、
emit 顺序、字段语义、所有权边界。本仓的现成范例：`abi/nostos_abi.h` 的
nostos_poster 注释（post 返回 OK 只代表"已入队"，会话作废时未排水的任务作废，
on_drop 是唯一回收出口）。

## 反面清单

- ✗ 复述代码：`// 遍历会话列表`（for 循环自己会说话）
- ✗ 变更日志：`已改为 X` / `不再 Y` / `以前是 Z`（历史归 commit）
- ✗ 对话式注释（对评审者说话）：`这里先这样，后面优化`——要么 TODO 要么删
- ✗ 注释掉的死代码——git 会记得，直接删
- ✗ 英文注释混入（技术名词/标记前缀除外）
