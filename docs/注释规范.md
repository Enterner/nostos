# ithaca 注释规范（所有 agent 与开发者共用）

> 与 `docs/测试规范.md` 同构的单一事实源。语言：**中文**（技术名词保留英文原词，不翻译）。

## 原则

1. **注释写 why，代码写 what。** 代码本身能看出来的，不写注释。
2. **注释自包含——代码是第一信息获取源。** 不写「详见 docs/xxx」「方案 §N」「见
   观察文档 F15」这类外指：注释要成立，必须把约束/背景/口径本身写进注释里，而不是
   让读者去别处查。文档可以存在，但代码注释不依赖它。
3. **陈述现状与不变式，不陈述历史。** 注释是给「半年后读代码的人」看的——他不知道
   旧行为是什么，「不再…」「已退役…」「修了…」这类变更日志式注释会随时间失效。
   历史进 commit message；注释里只留对新读者仍有价值的部分（约束的证据、事故的后果）。
4. 注释密度向「藏 complexity 的地方」倾斜：线程纪律、持久化时机、编码边界、契约顺序
   ——这些是注释的主战场；普通业务代码保持稀疏。

## 注释标记（统一前缀，可 grep）

| 标记 | 用途 | 示例 |
|------|------|------|
| `NOTE:` | 代码看不出来的约束/设计决定 | `NOTE: handle 内禁 broadcast——select 循环持 kit 内部锁再抢同一把锁 = EDEADLOCK` |
| `踩过:` | 违反上述约束的真实事故（接在 NOTE 后作证据） | `踩过: POST /api/input 即 500` |
| `TODO:` | 已知的待办，写明方向 | `TODO: pending 恢复可改为 SSE 重连事件驱动` |
| `HACK:` | 明知的取巧，说明为什么可以接受 | — |

## 各位置的写法

### 文件头（每个 .cpp/.h/.mjs/.vue）

一段职责说明 + 关键设计决定（**自包含**——不指向方案/设计文档，背景写进注释本身）。
参考 `plugins/webui/plugin.cpp` 头部（职责、两层持久化、线程纪律、锁纪律）。不加
版权/license 头——**闭源开发期不需要**；将来公开时统一补 SPDX 行
（`// SPDX-License-Identifier: <协议>` + 版权行），到时一次性脚本处理，平时不写。

### 分节横幅

大文件用 `// ---- 分节名 ----` 分节（现有风格），节名说职责不说过渡（写「会话注册表」
不写「辅助函数」）。

### 变更日志式注释的改写（存量，遇到就顺手改）

主句陈述现状规则；「踩过:」只留后果作证据。对照示例：

- ✗ `不再默认继承 host_workspace_（真实踩过：切过带工作区会话后，新会话全部被带偏）`
- ✓ `NOTE: 新会话的工作区由请求显式指定，不继承宿主当前工作区——继承会让切过带
  工作区会话后新建的会话全被带偏（踩过）`

- ✗ `修"汇总卡全堆在底部"：无 assistant 文本收口的轮次之前要等下一轮才结算`
- ✓ `NOTE: 轮次边界结算在 turn_id 变化时触发，保证无 assistant 收口的轮次（拒绝/
  报错轮）的编辑汇总也能落位，而不是堆到下一轮`

改写判据：把注释读给一个没看过 git log 的人——他能懂当前规则，即为合格。

### 公开面必须补文档注释（内部函数保持稀疏）

- `ui/src/store.js` 的每个 `export` 用 JSDoc 一段：职责 + 何时会发请求 + 失败行为。
  例：

  ```js
  /**
   * 进草稿态：＋新建后的空态引导。零请求——注册表/磁盘在首条消息前不动。
   * @param {string} [ws] 预选工作区（侧栏组「＋」带，主「＋新建」不带）
   */
  export function enterDraft(ws)
  ```

- `plugins/webui/plugin.cpp` 的 `api_*_` 函数用一行 `///` 说明契约：方法、参数、
  成功/失败返回、副作用（是否落盘/广播/开 turn）。例：

  ```cpp
  /// POST /api/session/new {message 必须, workspace?} → 创建即初始化：
  /// 注册+切换+首条落盘+开 turn 一次完成；裸调用 400。副作用：写注册表/transcript。
  ```

### 事件与契约注释

跨端点/跨事件的隐式契约必须写在生产者处（消费者处可留一行指回）：广播顺序、
emit 顺序、字段语义。参考 `start_turn_` 的「先广播用户消息再开 turn（顺序保证）」。

## 反面清单

- ✗ 复述代码：`// 遍历会话列表`（for 循环自己会说话）
- ✗ 变更日志：`已改为 X` / `不再 Y` / `以前是 Z`（历史归 commit）
- ✗ 对话式注释（对评审者说话）：`这里先这样，后面优化`——要么 TODO 要么删
- ✗ 注释掉的死代码——git 会记得，直接删
- ✗ 英文注释混入（技术名词/标记前缀除外）
